# 概念图 → 需求清单 + 设计规格

目标：把一张**静态图片**翻译成引擎能吃的**精确数据**，并且**诚实标注哪些是量出来的、哪些是猜的**。
本技能只做 Stage 0，不生成 PNG、不构建工程。工具与目录约定见 `squareline-ui-pipeline`
（`$TK`、`$SLX`、工程目录结构都在那里定义）。

## 步骤

### 0. 有需求文档？先做需求追溯（比看图更先）
`$SLX reqs extract concept/<文档>.md --proj <proj>` 把文档拆成带编号的原子需求（强度 MUST / MUST_NOT / SHOULD），
再 `reqs todo` 分批处理，逐条 `reqs set <ids> done --evidence "屏/对象" | deviation|out_of_scope|blocked --reason "…" | info`。
能自动验证的加 `--verify '{"type":"screen_exists","screen":"home"}'`（类型：canvas、screen_exists、screens_min、object_exists、object_hidden、
text_present、event_wired、event_exists、clickables_have、event_absent、asset_exists、asset_absent、font_min、reachable、no_errors、manual）。
抽取是启发式的：略读一遍，把非需求标 `info`，漏掉的用 `reqs add` 补。**文档里的"不得/禁止/必须"一条都不能漏**；
与概念图冲突的（例如文档禁止出现手而概念图里有手）逐条记为 deviation 并写进规格文档的风险表。
最终用 `reqs check` 验证、`reqs report` 生成 `需求追溯矩阵.md`。

### 1. 收件与分类
逐张看概念图（图片已在上下文里；要精确尺寸时用 `$SLX palette <img>`，它会打印原图像素尺寸）。分类：

| 类型 | 处理 |
|---|---|
| 单屏正面截图 / 效果图 | 直接量 |
| 多屏设计板（一张图里并排多个屏） | 先用 `grid` 找出每个屏的边界框，逐屏裁出来分别分析 |
| 设备实拍 / 带透视的渲染 | 屏幕是梯形，**不能精确量**；向用户要正面平面图，拿不到就标"估算"并加大容差 |
| 手绘草图 | 只取布局与层级，配色/字号走"提方案 → 用户确认" |

概念图一律先复制进 `<proj>/concept/`，后面所有引用都指向这份。

### 2. 一次性问清（≤1 轮，只问图里读不出来的）
- **面板分辨率与形状**（最关键）。用户不知道时，按图比例 + 常见面板推荐并标"假设"：
  圆形 240 / 360 / 390 / 412 / 454 / 456 / 466；矩形 240×280 / 320×385 / 368×448 / 410×502。
  圆形屏必须是正方形。
- 屏幕清单与切换方式（图里只有一屏时问"还有哪些屏、怎么进出"）。
- 界面语言（中/英/双语 → 决定字符集）。
- 交付物：`.spj` 工程 / 仅预览 / 都要；LVGL 版本默认 `9.2.2`。
- 资产偏好与许可要求（仅限商用可用许可？指定图标站？）。

用户不想答就按推荐值继续，并把每一条写进"假设"清单——**不许默默替用户决定**。

### 3. 建立像素换算
概念图里屏幕区域宽 `Wi`（量出来），面板宽 `Wp` → 比例 `s = Wp / Wi`。此后每个量到的像素乘 `s` 取整成面板坐标。
圆形屏：先量出圆的外接框（`grid` 叠网格），圆心 = 面板中心，`r = Wp/2`。
用 `$SLX grid <img> --step 50`、`$SLX crop <img> x0 y0 x1 y1 --zoom 3` 反复核对；**不要凭印象估坐标**。
**先让工具量一遍**：`$SLX scan <图> --find-screens` 找出设计板上的每块屏；再 `$SLX scan <图> --screen x0 y0 x1 y1 --panel <面板宽> --shape circle`
得到每个元素的面板 px 位置、颜色、类型提示（环/卡片/按钮/文字/图标）和字号估计，并生成**编号叠加图**——你只需要给每个编号命名（"心形图标""时间"），不需要自己定位。
它是启发式的，一定要对着叠加图确认。字号用 `$SLX fit-font "<文字>" --w <实测宽> --h <实测高> --weight 700 --cy <墨迹中心y> --ranges <该字体的字形范围>`
直接反算（真正的 lv_font_conv 度量，已验证与手动试错一致），不要靠目测。
量文字用 `$SLX bbox <img> x0 y0 x1 y1 --scale <Wp/Wi>`（默认抓近白像素；灰字加 `--color #98989F`），
直接得到面板 px 的位置与宽高，比读网格准。
容差目标：位置 ±4 px（面板坐标），颜色取样值，字号取最近的整档。**字号初值只是初值**：
首轮构建后要用同一方法在渲染图上复量并校正（见 `squareline-ui-pipeline` §5.6）。

### 4. 抽取设计令牌
- **配色**：背景、卡片、轨道/分割线、弱化文字、正文白、强调色。方法：`crop` 到纯色小块 →
  `$SLX palette <crop> --n 2`；别用全图主色代替元素色。命名成角色（`BG/CARD/TRACK/DIM/WHITE/ACCENT…`）。
- **字阶**：把图里的文字分 3–4 档（大数字 / 标题 / 正文 / 小注），量字高换算成 px 字号。
  字体只有随包的 Noto Sans SC 三个字重（700/500/400），**无法复刻概念图的原字体**——如实告知，
  只匹配字重与字号。数字大字用专用字体：`kind: "number"`，在 spec 的 `symbols` 声明 `"number": "0123456789:"`，并把 `ranges_num` 收到 `["0x30-0x3A"]`（否则整段 ASCII 都会进字体，体积大、行高被撑高）。
- **形态**：圆角半径、描边宽、环宽、间距节奏（量 2–3 处取规律值）。

### 5. 逐屏拆成引擎能画的元素
引擎只有 `PANEL / LABEL / IMAGE / ARC`。每个视觉元素先判可表达性，**不可表达的烘焙成 PNG，
文字与要交互的永远保持活对象**。判定表与烘焙做法见 `references/expressibility.md`，要点：

| 概念图里的东西 | 做法 |
|---|---|
| 纯色矩形/圆角矩形/圆 | `PANEL`（`radius` ≥ 半边长即圆） |
| 文字（含数字、单位） | `LABEL`（字号/字重/对齐/颜色） |
| 进度环、仪表弧 | `ARC`（`value/max/indicator/track/width/angles`） |
| 线性/填充图标 | `IMAGE`，资产由 `squareline-assets` 出 |
| 渐变、阴影、发光、模糊、噪点、玻璃拟态 | 烘焙进 IMAGE（builtin SVG），不要假装能用 PANEL 画 |
| 表盘刻度、指针、波形、迷你图表 | 预烘焙 PNG（指针固定 10:09:35 姿态） |
| 照片/插画 | 默认**重绘为矢量**或换占位；见下"原创与例外" |
| 动效（过渡、呼吸、脉冲） | 写进动画表，只用 `opacity` 等白名单属性；做不到的给替代方案 |

写每个元素时同时决定：`name`（屏内唯一）、`type`、`rect=[x,y,w,h]`（**屏幕绝对坐标**）、颜色、字体、内容。
LABEL 的 `h ≥ ceil(size×1.35)`；网格/卡片行用 `tools/layout.py`，别手算。
圆形屏逐个校验：可见元素外接框四角到圆心距离 ≤ r（留 ~5% 边距），靠上下缘的元素按弦宽收窄。

### 5.5 满铺位图要和外壳融为一体（3D/照片风格的帧）
当产品要求"画面和外壳颜色连成一体"（例如白色熊猫毛发铺满圆屏、外壳也是白色）：
- **不要靠圆形蒙版 + 黑底**：圆屏内仍会露出头部边缘/耳朵，黑底直接破坏融合。
- **以真实对称轴为中心裁切**（鼻子/眼睛中点，或头部轮廓左右上下边的中点），不要用"亮色包围盒"——深色耳根会把它拉偏几 px；
  每格单独量，偏差要限幅，免得装饰物（汗滴、眼泪）带偏。
- **只放大到屏幕落在主体白色区域内**：量头部椭圆，选裁切边长让五官完整、两侧留一点白；再对椭圆外用**主体白色径向延伸**填满。
  只采样"亮色低饱和"像素做延伸，五官/彩色装饰才不会被拖出。
- **接缝用"连续提亮"消除**：从约 45% 半径起，把**亮色像素**按平滑曲线提亮到外壳色（暗色五官不动）。
  只在边缘加一圈硬补，会露出一道椭圆接缝。
- **不要在边缘加任何光效/描边**（边缘光晕、环形装饰）——它们会给外壳色染色，直接违背"融为一体"。
- 用"模拟真机"图验收：把圆屏帧贴在外壳色背景上看（预览页自带的深色边框会掩盖融合问题）。
- 这类合成延伸只配做**设计期占位**；生产帧要让 3D 管线直接渲染满铺，并在规格文档里写清楚。

### 6. 交互与动画
静态图里**看不到交互**。只写能从图推断的（页码点/箭头暗示滑动、按钮外观暗示点击），其余列成问题问用户。
所有动作映射到白名单（`CHANGE_SCREEN/HIDE/SHOW/SET_OPACITY/PLAY_ANIMATION`）。屏幕顺序 = 滑动环顺序。

### 7. 文案与字符集
列出图中**全部**文字，再补"将来可能用的词"（单位、状态词、相邻功能词）。写进规格文档 §6.1。
中英双语把两种语言的全部词都列上。引擎找不到字形的符号（`℃ → ← ▶ 📍` 等 emoji/箭头）写进 `skip`，
需要的话改用图标。

### 8. 产出（写文件，不要只在聊天里描述）
1. `UI需求清单.md`：按模板填 §1 基本信息、§2 屏幕与切换、§3 逐屏粗排、§4 交互、§5 文案、§6 资产、§7 字体。
2. `<Name>设计规格文档.md`：**整份保留模板的全部小节**，把 §1–§8 填实：精确 `rect`、颜色、字体表、
   交互表、动画表、字符集、资产清单（含来源与许可列）。
3. `<Name>.spec.json`：把规格里的屏幕落成 spec（替换 `init` 生成的骨架），`fonts/ranges/palette` 按字阶与令牌填。
4. `assets.manifest.json`：图标清单（命名 `img_<屏>_<含义>[_<状态>][_<尺寸>]`，尺寸=对应 `rect` 的像素）。
5. `$SLX preview <proj> --strict` 先过一遍（此时缺图会画红框——正常，Stage A 之后补齐）。

### 8.5 需求书里的硬约束和概念图冲突时
需求文档（文字）和概念图（图片）常常互相打架。发现冲突时**不要悄悄选一边**：
- 约束优先于图：例如需求写"不得出现手"，但概念图的"思考"帧带手 → 该帧**排除**，用最接近的替代并在规格文档风险表里写明、请用户重做。
- 把冲突、取舍与理由写进规格文档的"已知偏差与风险"表，并在闸门 1 里列给用户。
- 概念图是**占位 vs 生产资源**的区别要说清：从设计板裁出来的脸只是设计期占位（分辨率、裁切），不是生产资源。

### 9. 闸门 1：给用户看什么
一张**确认表**，不是长篇大论：

- 面板：`W×H / 形状`（来源：用户给 / 反推 / 假设）
- 屏幕清单与顺序、每屏一句话
- 配色表（角色 → 色值）、字阶表（档 → px/字重）
- **假设与估算清单**：逐条写 `[测得]` `[估算]` `[假设]`，估算/假设项要说明影响（比如"字体无法复刻"）
- 需要用户决定的问题（≤5 个，每个给默认值）

用户确认后才进入 `squareline-assets`。

## 原创与例外

默认**不从概念图里裁位图当资产**：图标走 Lucide/图标站/自绘 SVG，装饰用 builtin SVG 重绘。
这样既规避版权/品牌问题，也避免"放大糊、边缘带背景色"的抠图缺陷。
**例外**：概念图是用户自己的作品，且用户明确说"这块插画/照片/logo 就用图里的"——这时可以用
`$SLX crop` 裁出来作为位图资产，并在规格文档 §7 资产清单记 `来源：用户概念图（用户确认可用）`。
引用第三方产品（如某品牌手表）时，只借设计语言，不复制其图形/logo（见 `squareline-ui-pipeline` §9）。

## 不要做的事

- 不要在没量之前写坐标；不要把"看起来差不多"当作 `[测得]`。
- 不要因为图里的字体好看就承诺能复刻。
- 不要为了凑满概念图而塞进引擎画不出的效果；烘焙或替代，并告诉用户。
- 不要跳过闸门 1 直接生成资产/构建。
