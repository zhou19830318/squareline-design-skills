# AI手表 UI 设计规格文档
基于 ESP32-S3 2.06寸 AMOLED 触控开发板（分辨率 **410×502px**，QSPI接口，双麦克风阵列）
用于 SquareLine Studio + LVGL v8.x 界面搭建

> 屏幕基础参数：分辨率 410×502，圆角矩形表盘（非全圆形），建议 LVGL 工程设置为 `Resolution: 410x502`，`Color depth: 16bit (RGB565)` 或按面板驱动实际（多为 QSPI + RGB565/RGB666）。
> 全局坐标系：以屏幕左上角为 (0,0)，X 向右，Y 向下。

---

## 通用组件规范

| 组件 | 规格 |
|---|---|
| 状态栏时间文字 | 字体 16-18px，白色 `#FFFFFF`，右上角，格式 `HH:MM` |
| 顶部标题栏高度 | 约 40-46px |
| 应用图标（圆形按钮） | 直径 64px，纯色背景圆 + 白色线性图标 28-32px，居中 |
| 图标下方标签文字 | 12-13px，白色，居中，与图标间距 4-6px |
| 列表行高 | 约 64-70px，含分隔线 1px `#2A2A2A` |
| 强调色/主色 | 粉色 `#FF2D8A`（播放/进度）、绿色 `#3DD874`（计步）、红橙 `#FF5A3C`（番茄钟）、蓝色 `#3B82F6`（时间/天气/蓝牙）、紫色 `#8B5CF6`（AI/音乐） |
| 卡片圆角 | 20-24px |
| 背景色（非壁纸页面） | 纯黑 `#000000`（AMOLED 省电） |

## 1. 总览预览（App Grid / 主页九宫格）

**用途**：手表主菜单，表冠/触控进入各功能模块入口。

### 布局结构
```
[10:27]                          [🔋78%]
[4月26日 周六]

  (64)      (64)      (64)
  时间       天气      AI对话

  (64)      (64)      (64)
 番茄时钟    计步       MP3

           (64,居中)
            设置
```

### 坐标细节（410×502画布）
- 状态时间 `10:27`：位置 x=24, y=20，字号 28px 粗体，白色
- 日期 `4月26日 周六`：位置 x=24, y=56，字号 14px，灰白 `#CCCCCC`
- 电池图标+百分比：右对齐，x≈300-386, y=24，图标18×10px + 文字14px
- 图标网格：3列×2行，容器起始 y=110，行间距 96px，列间距 (410-3×64)/4≈54px 均分
  - 第1行 y=110~174：时间(蓝)/天气(蓝)/AI对话(紫)
  - 第2行 y=210~274：番茄时钟(红)/计步(绿)/MP3(紫)
- 底部设置按钮：水平居中，x=173, y=330~394，图标为齿轮，标签"设置"

### LVGL 控件建议
- 用 `lv_obj` 作为 Grid container（`lv_flex` 或 `lv_grid`，3列布局）
- 每个应用入口 = `lv_btn`(圆形，`lv_obj_set_style_radius(LV_RADIUS_CIRCLE)`) + 内嵌 `lv_img`(图标) + 下方 `lv_label`
- 点击事件跳转到对应 Screen（SquareLine 中用 "Screen Load" action）

### 所需图片/图标资源
| 资源 | 尺寸 | 格式 | 说明 |
|---|---|---|---|
| 时钟图标 | 32×32 | PNG(透明) | 白色线条 |
| 天气图标(晴云) | 32×32 | PNG | 白色线条 |
| AI机器人图标 | 32×32 | PNG | 白色线条 |
| 番茄图标 | 32×32 | PNG | 白色/彩色 |

### 数据/API 依赖
- 系统时间：ESP32 RTC + NTP（WiFi连接时同步，`sntp_setoperatingmode`）

## 3. 天气

### 布局细节
- 顶部栏 y=20-46：左侧 📍图标(16×16)+"北京"(16px)，右侧"10:27"(16px)
- 主体天气区 y=70-160：
  - 左侧大图标（太阳+云）72×72，x=24
  - 右侧 "18°C" 大字 48px粗体，x=110
  - 其下 "多云" 16px灰白
  - 再下 "22°/12°" 14px灰白 + 右侧 ">" 箭头（点击进入15天预报）
- 分隔线：y=210，1px `#2A2A2A`，左右留白24px
- 逐时预报行 y=230-300：4列等分（每列约90px宽）
  - 每列纵向排列：时刻文字(如"11时",12px) → 天气小图标(28×28) → 温度(16px)
  - 数据："11时/20°"、"14时/21°"、"17时/19°"、"20时/16°"
- 底部：屏幕最下方居中的小胶囊拖拽指示条（宽36×高4，灰色圆角），提示可上滑查看更多

### LVGL 控件建议
- `lv_label` + `lv_img` 组合展示主天气
- 逐时预报用 `lv_flex`(横向, space_evenly) 容器包裹4个子容器
- 拖拽指示条可用简单 `lv_obj` 矩形圆角模拟，或直接用 `lv_obj_add_event_cb` 实现上滑手势切换到15天预报页

### 所需图片资源
| 资源 | 尺寸 | 格式 |
|---|---|---|
| 天气大图标（晴/多云/雨/雪/雷等全套） | 72×72 | PNG，每种天气状态一套 |
| 天气小图标（同上套图缩小版） | 28×28 | PNG |

### 数据/API 依赖（重点）
需要接入天气API（通过 WiFi HTTPS 请求），推荐：
- **和风天气 QWeather API**（国内数据全、有免费额度）：`GET https://devapi.qweather.com/v7/weather/now` 及 `/v7/weather/24h`
- 或 **心知天气 Seniverse API**
- 或 **OpenWeatherMap**（国外，需科学上网/海外服务器）

请求需要参数：城市经纬度或 LocationID、API Key
返回解析字段：
- 实时：`temp`(当前温度), `text`(天气描述), `icon`(图标代码), `tempMax`/`tempMin`
- 逐时：`time`, `temp`, `icon` 数组（取未来4-8小时）

ESP32端建议：
- 使用 `esp_http_client` 发起 HTTPS GET
- `cJSON` 解析返回 JSON
- 图标代码映射到本地存储的 PNG 图标（因为设备端不便动态下载图片，需预置图标集并按 icon code 映射）
- 建议缓存+定时刷新（如每30-60分钟一次），避免频繁请求耗电耗流量

## 4. AI对话

### 布局细节
- 顶部栏 y=20-46：左侧 紫色圆形机器人/对话图标(24×24)+"AI对话"(18px)，右侧"10:27"
- 对话气泡区 y=60-140：
  - 头像：蓝紫渐变圆形机器人图标，44×44，x=24, y=64
  - 消息气泡：深蓝紫色圆角矩形(`#2A2A4A`附近)，圆角16px，x=80, y=64，宽约280，内边距12px，文字"你好！有什么我可以帮你的吗？" 15px白色
- "历史对话" 标题行 y=170：左侧文字16px白色，右侧">"箭头（进入完整历史列表）
- 历史列表 y=200 起，每项高约60px：
  - 左侧小图标：蓝色圆形对话气泡图标 28×28
  - 右侧两行文字：主标题(白色15px，单行省略) / 时间戳(灰色12px，如"04-26 09:15")
  - 示例3条：帮我写一份项目计划书 / 明天天气怎么样？/ 推荐一些适合阅读的书

### LVGL 控件建议
- 消息气泡用 `lv_obj` 圆角容器 + 内嵌 `lv_label`（长文本自动换行 `lv_label_set_long_mode(LV_LABEL_LONG_WRAP)`）
- 历史列表用 `lv_list` 或自定义 `lv_obj` + `lv_flex` 纵向排列，可滚动（`lv_obj_set_scroll_dir(LV_DIR_VER)`）
- 麦克风唤醒/录音时可加一个悬浮麦克风按钮或波形动画（板载双麦克风阵列用于拾音）

### 所需图片资源
| 资源 | 尺寸 | 格式 |
|---|---|---|
| AI机器人头像图标 | 44×44 | PNG |
| 对话历史小图标 | 28×28 | PNG |
| 麦克风/录音波形动画帧（可选） | 自定 | PNG序列或矢量动画 |

### 数据/API 依赖（核心功能）
这是本手表的核心AI能力，需要：
1. **语音输入**：双麦克风阵列采集音频 → 本地做简单VAD(语音活动检测)/降噪 → PCM音频流
2. **STT（语音转文字）**：
   - 接入"小智AI"生态（其开源方案基于 WebSocket 与云端服务器通信，支持实时流式ASR）
   - 或直接调用 **DeepSeek API**（文本对话）配合第三方ASR（如讯飞、阿里云、百度语音识别）先转文字
3. **对话大模型**：
   - **DeepSeek Chat API**：`POST https://api.deepseek.com/chat/completions`，Header需 `Authorization: Bearer <API_KEY>`，Body含 `model`, `messages`(role/content数组)，支持流式`stream:true`
4. **TTS（文字转语音）**：将模型回复合成语音，通过I2S功放播放（讯飞/阿里云/微软 Azure TTS 等，或小智AI内置TTS服务）
5. **网络**：需 WiFi 联网，ESP32-S3 使用 `esp_websocket_client` 或 `esp_http_client` 实现流式通信
6. **本地存储**：历史对话记录建议存于 SPIFFS/LittleFS 或外挂 SD 卡，JSON格式存储 `{title, timestamp, content}`，用于历史列表展示
7. 建议架构：设备仅做音频采集/播放+UI展示，STT/LLM/TTS均在云端或本地网关（如"小智AI"后端服务器）处理，减轻MCU算力压力

## 6. 计步

### 布局细节
- 顶部栏 y=20-46：左侧 绿色跑步人图标(22×22)+"计步"(18px)，右侧"10:27"
- 中央圆环：结构同番茄钟，绿色渐变(`#3DD874`)，圆心 x=205, y=230
  - 环内：鞋子图标(28×28，居中偏上) + 大号步数"6820"(48px粗体) + "步"单位字(16px灰白，紧贴数字右下)
- 环下方统计行 y=370，左右两个统计块：
  - 左：火焰图标(20×20,橙色)+"320"(20px)+"卡路里"(12px灰白)，块居中x=140
  - 右：定位图标(20×20)+"4.8"(20px)+"公里"(12px灰白)，块居中x=270
- 底部：单个灰色圆形按钮(48×48)+柱状图图标，位置水平居中偏下 y=430（进入详细统计/历史趋势页）

### LVGL 控件建议
- 同番茄钟用 `lv_arc`，进度按"当日步数/目标步数"计算百分比
- 统计块用两个并排 `lv_obj` flex 容器，各自纵向排列 图标+数字+标签

### 所需图片资源
| 资源 | 尺寸 | 格式 |
|---|---|---|
| 跑步人图标 | 22×22 | PNG |
| 鞋子图标 | 28×28 | PNG |
| 火焰图标 | 20×20 | PNG |
| 定位图标 | 20×20 | PNG |
| 柱状图图标 | 24×24 | PNG |

### 数据/API 依赖
- **计步算法**：基于板载IMU（加速度计，如需确认具体传感器型号——常见方案为外挂 QMI8658/MPU6050 等I2C加速度计），通过加速度峰值检测算法实现计步（可用现成的 Pedometer 算法库或自行实现基于阈值+滑动窗口的检测）
- **卡路里估算**：基于步数×体重×步幅经验公式本地计算，无需联网
- **距离(公里)**：步数×平均步长估算；若需精确定位轨迹需外接GPS模块（该开发板需确认是否板载GPS，若无则仅做估算）
- 数据本地存储于 Flash（NVS），按日重置，历史数据可选存 SD 卡供趋势图使用
- 可选：通过 BLE 同步步数到手机健康类 App

- 播放列表/进度状态可本地NVS保存，重启后续播

## 8. 系统设置

### 布局细节

### 数据/API 依赖
- **蓝牙**：ESP32-S3 BLE协议栈（`esp_bt`），配对状态读取/连接管理
- **亮度**：控制AMOLED驱动IC的背光/亮度寄存器（QSPI屏一般通过写入面板寄存器控制亮度，或PWM控制），"自动"模式需光线传感器（需确认该开发板是否板载环境光传感器ALS，若无则只能手动调节）
- **声音**：本地音量变量控制I2S输出增益或数字音量
- **语言**：本地多语言字符串表(i18n)，LVGL可用 `lv_i18n` 组件管理多语言资源，切换后刷新所有Label文本
- **关于本机**：显示固件版本号、MAC地址、可用存储空间等本地系统信息
- 所有设置项建议持久化存储于 NVS（ESP-IDF的Non-Volatile Storage），重启后保留

### 通用导航手势建议
- 表冠/侧边按键：返回主页 / 确认
- 左右滑动：在同级页面切换（如首页各功能卡片式滑动）
- 上滑：查看更多详情（如天气页上滑进入15天预报）
- 长按主页图标：可选进入编辑/卸载模式

### 固件侧API对接优先级建议
1. 时间/日期（RTC+NTP）—— 最基础，无外部依赖
2. 设置模块（蓝牙/亮度/声音/语言）—— 纯本地
3. 计步（IMU算法）—— 需确认传感器型号
4. 番茄时钟 —— 纯本地定时器
5. 天气（第三方天气API）—— 需WiFi+API Key
6. MP3播放（本地SD卡音频解码）—— 需esp-adf音频框架
7. AI对话（小智AI/DeepSeek接入，STT+LLM+TTS全链路）—— 最复杂，建议最后集成，依赖WiFi+云端服务

### 需要向硬件/固件确认的开放问题
- 该开发板是否板载 IMU 加速度计（用于计步）、环境光传感器（用于自动亮度）、GPS模块（用于精确距离/定位）
- 蓝牙是否支持经典蓝牙A2DP（音乐传输）还是仅BLE
- 音频输出为I2S功放还是内置扬声器规格（决定MP3播放实现方式）
- Flash/SD卡容量，决定壁纸、音乐、历史对话等本地存储方案
