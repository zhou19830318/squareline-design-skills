# 设计规格文档模板

> **用途**：这是 Stage 0 的输入契约。本文件就是「源真相」（source of truth）——
> 后续每个阶段都只对着它验收，不再回头猜需求。
>
> **怎么用**：整份复制到 `examples/<项目名>/<项目名>设计规格文档.md`，把 `<>`
> 占位内容换成本项目的真实数值。请**保留全部小节**：即使某节为空，也写「无」，
> 因为下游工具与评审都按小节定位信息。
>
> **两个硬性约定**（不做就等着返工）：
> 1. 所有 `rect` 一律写 **屏幕绝对坐标**（左上角原点），不要写相对容器的偏移。
>    引擎会在落盘前统一 `rebase()` 成 SquareLine 的「相对父中心」形式。
> 2. 正文里把界面**可能出现的全部文案**都写出来（见 §6 文案字符集）。
>    构建时会收录本文档的每一个字符进字体子集——这是将来改文案不缺字形的唯一保障。

| -------- | ---- | ------- | ---- | ------ |

### 6.1 文案字符集（glyph headroom）★ 必填

> **把界面可能出现的所有文案写进这一节**（含将来才会用到的词）。
> 构建时会收录**本文档的全部字符**打进字体子集，这就是改文案时的余量。
> 纯数字字体不要声明全角 CJK 区段（会 3 倍体积）。

- 首页：`步数 8642 步 左滑进入设置`
- 设置：`显示 自动 手动 关于本机 版本 v1.0`
- 预留：`心率 血氧 睡眠 卡路里 距离 天气 温度 电量 充电 同步 通知 免打扰 亮度 音量 语言 重置 确定 取消`

**多语言变体**：若界面要切语言，把每种语言会用到的文案**全部**写在这里
（中/英/日…），并按需在 `ranges_text` 里加上对应区段（如日文假名
`0x3041-0x3096`、`0x30A1-0x30FA`）。漏写 = 切到该语言时有字打不出来。

需要但从字体里确认缺失的字符（写进 `skip`，否则会报缺字形）：
```
℃ ≈ ├ 📍 ⚠ 💡 ⏸ → ← 🔋 ▶ ─
```

> 小技巧：`0x20-0x7E`（不是 `-0x7F`，U+007F 任何字体都没有）；
> 全角块 `0xFF01-0xFF5E` 里 Noto Sans SC 缺 `ｊ`(U+FF4A) 与 `ｚ`(U+FF5A)，
> 想彻底消掉告警就拆成 `0xFF01-0xFF49`、`0xFF4B-0xFF59`、`0xFF5B-0xFF5E`。

## 7. 资产清单

| 文件 | 尺寸 | 用途 | 生成方式 |
| ---- | ---- | ---- | -------- |
| `assets/images/img_step.png` | 64×64 | 步数图标 | `generate_assets.mjs`（Lucide `footprints`） |

> 无位图资产的项目写「无（纯几何 + 文字）」，并在规格 JSON 里把 `assets` 留空。

### 7.1 命名规范与资源清单

- 文件名一律 `img_<屏/域>_<含义>[_<状态>].png`（如
  `img_apple_ai_mic_listening.png`、`img_weather_icon_rain_72.png`）；
  尺寸差异用后缀（`_24` / `_72`）区分，不要靠目录区分。
- 引用路径写在对象表的 `asset` 字段里，**相对工程目录**（`assets/img_*.png`）。
- 复杂工程另出一份 **资源清单**（如 `examples/AIWatch/AIWatch图片字体资源清单.md`），
  逐条对齐「文件 ↔ 界面用途 ↔ 来源（Lucide 图标名 / 自绘 SVG）↔ 归属屏」。
  规格文档负责「哪个对象用哪张图」，资源清单负责「这张图从哪来、怎么改」——
  两者是同一批资源的两个视角，改图时两份都要动。
- 构建时引擎会把「对象引用到的图」复制进工程；**没被任何对象引用的图不会进工程**。
  反过来，对象引用了不存在的图，validator 会报 `missing image files`。
