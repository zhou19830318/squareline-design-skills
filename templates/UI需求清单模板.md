# UI 需求清单模板

> **用途**：这是用户交给 agent 的**需求文件**（配合概念图使用）。它是 Stage 0
> 设计规格文档的**上游输入**：需求清单用自然语言描述「要什么」，设计规格文档
> 用精确坐标描述「怎么做」。agent 读概念图 + 本清单 → 产出设计规格文档 →
> 再走资产生成 / mockup / 构建校验流水线。
>
> **怎么用**：整份复制为 `examples/<项目名>/UI需求清单.md`，把 `<>` 占位内容
> 换成真实需求。**允许留空**——标「待定」的项由 agent 在 Stage 0 提出方案、
> 经确认后写进设计规格文档。唯一必须给全的是 §1 的基本信息与 §2 的屏幕清单。
>
> **多轮优化**：每轮修改意见直接追加在 §9 的迭代记录表里，agent 据此更新
> 设计规格文档并重新构建，而不是口头重述。
